Pool Shed v1.21.0 - Legacy Data Migration
==========================================

Release purpose
---------------
Recover useful operational information from earlier Pool Shed generations and merge it into the current v1.20+ canonical workspace without bringing old UI/code back into production.

Migration sources
-----------------
- poolbros:system:appData
- poolbros:*:appData user snapshots
- IndexedDB: the-pool-shed-offline / state / appData
- Authenticated, read-only legacy Supabase offline_sync_snapshots when available
- Manual JSON snapshot import

Covered data
------------
Suppliers, customers, products/SKUs, locations, projects/jobs, Sales Orders,
Purchase Orders, standalone legacy sales history, stock balances, allocations,
stock movements, Goods Notes, Engineer Requests, Sales Credits and notifications.

Safety
------
- Dry run before apply
- Current populated values win
- Legacy values only enrich blanks or create genuinely missing records
- Existing current stock balance wins; legacy quantity is never added to it
- Ambiguous identity matches are reported as conflicts
- Complete pre-migration backup before apply
- Apply uses the existing Pool Shed save/sync path
- Existing auth, permissions and Xero connection state are not replaced

Verification
------------
Supported regression matrix: PASS
Production build: PASS
Release asset audit: PASS (51 referenced assets; JS parses)
Dist runtime validation: PASS

Known extracted-runtime limitations, unchanged from v1.20:
- Full validate stops at database-only test because @electric-sql/pglite is not installed
- Browser automation cannot start because playwright is not installed

Use
---
Sign in as Admin, open Settings > Legacy Data Migration, scan/import the legacy
source, run Dry Run, review conflicts, download/confirm the backup and only then
apply the migration.
