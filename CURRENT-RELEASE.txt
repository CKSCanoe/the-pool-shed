Pool Shed v1.49.0 - fast per-record saving and refresh

Saving now sends only the records you changed (typically 1-3 KB) instead of the whole 7 MB workspace, so saves are several times faster and no longer hit the server time limit. When two people edit different records at the same time, both changes are kept; only two people changing the same record get a clash. Other open tabs download only the records that changed. If anything does not line up, the app falls back to the full save or download it used before. Also fixes false "Another user saved first" messages after two quick edits.

When someone saves, other open tabs now download only the records that changed (typically 1-10 KB) instead of the whole 7 MB workspace. If anything does not line up, the tab downloads in full exactly as before. Also fixes false "Another user saved first" messages after two quick edits by the same person: the saved revision stamp now matches the one returned to the app.

Pool Shed v1.48.0 - Supabase egress fix and lighter start-up

Shared-workspace sync now checks only the tiny revision stamp every 8 seconds while the tab is visible, and downloads the workspace only when another user has saved. Hidden tabs make no requests; returning to a tab checks immediately.
The realtime subscription on workspace_snapshots is removed. It pushed the complete multi-megabyte workspace row to every open tab on every save. Quote engagement refresh also pauses while the tab is hidden.
The app logo is now 256 px (50 KB, was 1254 px / 420 KB). Design-lab mock-ups are no longer deployed (moved to docs/design-labs). Duplicate function entry removed from vercel.json.
Stock-count reminders no longer re-create the same alert every day. Each copy forced a full workspace save and another full copy in ps_workspace_revisions; 45 duplicates had built up. Simultaneous refresh triggers (tab focus, online event, timer) now download at most once.

No database migration, no data change. Behaviour test: scripts/test-egress-sync-v148.mjs (idle hour: 0 full downloads, was 720).

Pool Shed v1.47.1 - supplier payment operations and Sales Order costs

Finance Command now separates unpaid proforma Purchase Orders from on-account payables. Proforma orders are due in full before supplier release and require an actual supplier payment with a reference; they do not enter the payment run. On-account bills enter a payment run only after the PO, receipt and invoice match, and an outstanding balance remains.

Rach can choose a due-date range, include already overdue bills, run a review, select items, create a saved draft payment batch, inspect and export it, or cancel the draft. Creating a batch never records a bank payment. The PO now records supplier invoice and payment due dates. A clear Net N days term can calculate a due date from the invoice date; an explicit due date takes precedence. Bills with no due date are called out for review.

Each PO line can link to a non-Project Sales Order. Finance Command shows indicative Sales Order gross profit from linked PO costs and flags incomplete coverage. This is an operational estimate, not a final ledger profit calculation. Projects retain their own reporting.

Shared workspace saving, audit links and existing records remain intact. Xero remains the accounting ledger and any PO/Xero balance discrepancy is marked for reconciliation.

Live follow-up: when a Sales Order has incomplete PO cost coverage, the profit and margin cells remain Pending rather than displaying a misleading 100% margin.
