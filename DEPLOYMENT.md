# Pool Shed Deployment Guide

## Prerequisites

- Node.js 18+
- npm or yarn
- Supabase project (https://supabase.com)
- Vercel account (optional, for hosting)

## Local Development

### Setup

```bash
# Clone repository
git clone https://github.com/CKSCanoe/the-pool-shed.git
cd the-pool-shed

# Install dependencies
npm install

# Create .env from template
cp .env.example .env
```

### Environment Variables

Edit `.env` with your Supabase credentials:

```bash
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_PUBLISHABLE_KEY=your-anon-key
NODE_ENV=development
```

### Local Testing

```bash
# Validate code without deploying
npm run validate

# Run specific feature tests
npm run test:health
npm run test:fulfilment
npm run test:bundles

# Build for testing
npm run build

# Serve dist/ with any HTTP server
python3 -m http.server --directory dist 8000
# Visit http://localhost:8000
```

## Deployment

### Via Vercel (Recommended)

1. **Connect Repository**
   - Log in to https://vercel.com
   - Click "New Project"
   - Import `CKSCanoe/the-pool-shed`

2. **Set Environment Variables**
   - Project Settings → Environment Variables
   - Add:
     ```
     SUPABASE_URL=https://your-project.supabase.co
     SUPABASE_PUBLISHABLE_KEY=your-anon-key
     NODE_ENV=production
     ```

3. **Configure Build**
   - Build Command: `npm run build`
   - Output Directory: `dist`
   - Install Command: `npm install`

4. **Deploy**
   - Click "Deploy"
   - Vercel runs validation automatically
   - View at `https://the-pool-shed.vercel.app`

### Via Git Push

If Vercel is configured, simply push to trigger deployment:

```bash
git push origin main
```

Vercel automatically:
1. Runs `npm install`
2. Runs `npm run build`
3. Validates with `npm run validate`
4. Deploys to CDN if successful

### Manual Deployment

```bash
# Build
SUPABASE_URL="https://..." \
SUPABASE_PUBLISHABLE_KEY="..." \
npm run build

# Upload dist/ to your hosting provider
# (AWS S3, Google Cloud Storage, Azure, etc)
```

## Pre-Deployment Checklist

- [ ] `.env` file NOT committed (in `.gitignore`)
- [ ] `npm run validate` passes
- [ ] All feature tests pass: `npm run test:*`
- [ ] Supabase credentials are valid
- [ ] Service worker cache keys updated (if needed)
- [ ] No console errors in browser DevTools
- [ ] Offline mode tested
- [ ] Critical workflows tested (sales order, fulfillment)

## Troubleshooting

### Build Fails: "Missing required deployment file"

The validation script checks for required files. Ensure:
- `public/config.js` exists (generated by build.sh)
- All asset files are present
- Service worker cache list is up-to-date

### Supabase Connection Fails

```javascript
// In browser console
PoolShedConfig.get('supabaseUrl')         // Should not be empty
PoolShedConfig.get('supabasePublishableKey') // Should not be empty
```

If empty:
1. Check `.env` file
2. Rebuild: `npm run build`
3. Clear browser cache
4. Check `dist/config.js` contains credentials

### Validation Errors

```bash
# Run validation with detailed output
node scripts/validate-runtime.mjs dist
```

Common issues:
- Missing CSS/JS files in `public/assets/`
- Service worker cache list incomplete
- Syntax errors in JavaScript
- Feature file mismatches

### Service Worker Issues

```javascript
// In DevTools → Application → Service Workers
// Should show: pool-shed-app-v1-po-picker-modal-final-clean

// Clear cache if stuck
navigator.serviceWorker.getRegistrations().then(regs => {
  regs.forEach(reg => reg.unregister());
});

// Hard refresh (Cmd+Shift+R or Ctrl+Shift+R)
```

## Security

### Secrets Management

✅ **Do:**
- Store credentials in `.env` (local)
- Use Vercel Environment Variables (production)
- Use Supabase public/anonymous key only
- Rotate keys periodically

❌ **Don't:**
- Commit `.env` files
- Use admin keys in client code
- Expose credentials in error messages
- Log sensitive data

### CORS & CSP

- `vercel.json` configures headers
- Assets have long cache TTLs
- Service worker updates checked daily
- Cross-origin requests require Supabase config

## Performance

### Optimize Bundle Size

```bash
# Analyze current size
wc -c dist/*.js dist/assets/**/*.js

# Measure load time
node scripts/performance-audit.mjs
```

### Cache Strategy

- **Assets** (`/assets/*`): 1 year (immutable)
- **Stylesheets/Scripts** (`.css`, `.js`): 1 day
- **index.html**: No cache (always fresh)
- **service-worker.js**: No cache

See `vercel.json` headers section.

## Support

If deployment fails:

1. Check Vercel build logs
2. Run `npm run validate` locally
3. Verify `.env` variables
4. Check browser console (DevTools)
5. Inspect `PoolShedErrorHandler.getHistory()`
