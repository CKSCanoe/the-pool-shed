# Pool Shed Legacy UI Isolation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stop legacy Pool Shed presentation code and stale cached assets from overriding the approved Dashboard, Customer and Sales Order workspaces while preserving existing stock, CRM, fulfilment, accounting and offline business engines.

**Architecture:** Keep the legacy runtime as the business/data engine, but establish deterministic final presentation ownership. Version every local runtime asset as one release, fence old DOM polish away from the modern Sales Order command surface, and make the design system the sole owner of shared hover/control primitives. Extend regression tests so mixed-generation assets and reintroduced legacy UI mutations fail before release.

**Tech Stack:** Vanilla HTML/CSS/JavaScript, Node.js test scripts, service worker/PWA cache, existing Pool Shed build scripts.

**Spec:** Approved Design Lab implementations and the v1.7.3 production baseline in this package, including CUSTOMER-DESIGN-PARITY-AUDIT.md and DEEP-AUDIT-1.6.2.md.

## Global Constraints

- Preserve all business/data engines and offline-first local/IndexedDB/sync behaviour.
- Preserve Sales Order Smart Product Finder behaviour and exact-variant selection.
- Preserve selected Dashboard Option A, Customer master-detail composition and Sales Order Order Command/Precision Row hierarchy.
- Do not reintroduce dark-green product-selection hover states; green remains semantic stock/readiness feedback.
- Production must load one deterministic app.css bundle.
- No legacy presentation mutation may rewrite the modern Sales Order command DOM.
